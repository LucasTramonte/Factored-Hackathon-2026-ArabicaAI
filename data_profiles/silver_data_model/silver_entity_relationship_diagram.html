Worth knowing before you rely on this as a contract: none of these relationships are enforced by DuckDB — there are no REFERENCES constraints anywhere in the Silver build. PK here only drives the QUALIFY row_number() … = 1 dedup in silver.py; FK is a column that happens to match another table's key. A row with an orphaned FK (a customer_id with no matching dim_customers row, say) will build without error — worth a row-count / orphan check before trusting joins across these tables in analysis.
